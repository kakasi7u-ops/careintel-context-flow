# CareIntel Context

You are not building a generic AI landing page.

You are designing and implementing a premium, human-designed, enterprise healthcare technology website for a product called:

CAREINTEL

A multimodal healthcare triage assistant for government and institutional health facilities.

The visual and content quality should feel comparable to a carefully designed $2,000+ custom product website created by an experienced product designer, UX strategist, visual designer, copywriter, and frontend engineer.

The website must feel:

- premium

- intelligent

- trustworthy

- modern

- calm

- human

- technically credible

- healthcare-native

- sophisticated

- memorable

It must NOT feel:

- AI-generated

- template-based

- generic SaaS

- overdesigned

- childish

- like a medical stock-photo website

- like a ChatGPT wrapper

- like a dashboard pretending to be a landing page

==========================================================

CORE PRODUCT TRUTH

==========================================================

CareIntel is a non-diagnostic, human-in-the-loop healthcare triage support system.

It helps organize multimodal patient-provided information and prepare structured, evidence-linked information for qualified human review.

Core capabilities include:

- text intake

- voice input

- document processing

- image input

- OCR

- speech-to-text

- structured information extraction

- provenance

- timeline construction

- missing information detection

- follow-up questions

- trusted knowledge retrieval

- AI-assisted reviewer-facing draft generation

- deterministic safety validation

- human review

- escalation

- referral

- handoff

The website must never present CareIntel as:

- a doctor

- an autonomous diagnostic system

- a replacement for clinicians

- an autonomous clinical decision maker

- a prescribing system

- a system that guarantees medical outcomes

Never use language such as:

- “diagnoses patients”

- “replaces doctors”

- “guarantees diagnosis”

- “makes clinical decisions automatically”

- “100% accurate”

- “eliminates medical errors”

- “saves X%”

- “reduces diagnosis time by X%”

unless an explicitly provided source supports the claim.

Do not invent:

- patient outcome statistics

- accuracy percentages

- hospital partnerships

- government partnerships

- customer logos

- testimonials

- awards

- clinical certifications

- regulatory approvals

- deployment numbers

- user numbers

- performance benchmarks

- funding information

If data is not provided, do not create it.

==========================================================

Apply these principles deliberately:

1. Cognitive fluency

The user should understand each section immediately.

2. Progressive disclosure

Do not reveal all technical detail at once.

3. Visual anchoring

Alternate dense technical sections with calm editorial sections.

5. Trust formation

Show evidence, provenance, safety and human oversight before asking for trust.

6. Emotional resonance

Use real healthcare contexts and human-centered storytelling.

7. Information hierarchy

“AI-assisted. Evidence-linked. Human-led.”

“Safety is part of the architecture.”

Remove them.

Are images generic?

Does the page communicate healthcare context?

Improve it.

Keep it.
